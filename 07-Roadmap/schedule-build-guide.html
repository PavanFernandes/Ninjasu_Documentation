Cancel and refund

  • Customer cancels the whole group before the earliest locked cutoff: one full refund.
  • After the cutoff the customer cannot cancel.
  • A restaurant decline or ops cancel refunds that order only, as a partial refund on the group payment.
  • Refund rows are locked so the total never exceeds what was captured, and the delivery fee is refunded once.

Why a status, not a time filter

The live board lists every status that is not finished. A time filter would have to be remembered by every reader forever. A separate SCHEDULED status keeps these orders off the board by construction, and a test makes every status belong to exactly one group.

Two numbers per dish

Cutoffs and stock

Each dish, each day has a stock and an order-until time, both editable by the restaurant at any moment. The area adds one rule: a last call before each slot, because riders need the orders in time.

11:30Biryani order-until. Bulk ticket released.
12:00Slot last call. Nothing can be ordered for 12:30.
12:10Ready by. Rider pickup.
12:30Delivery slot.

Zepto-style restock

Biryani bulk 50, order until 11:30
Extra +15, order until 1:00 pm

Spice Hub cooks extra: it raises stock to 65 and moves order-until to 1:00. The dish reappears on the next refresh. The extra stock can only be ordered for the 1:30 slot, because the 1:00 slot's last call is 12:30.

The rules

  • Raise stock any time; lower it only down to what is already ordered.
  • Move order-until earlier or later, including reopening a closed dish.
  • A dish shows "order by 11:30", "sold out" or "closed for this slot", greyed but visible.
  • An order's cutoff is locked when it is paid. Later edits never change it.
Marketplace pricing

Money

The restaurant gets its dine-in price as the split price. Commission is built into the menu price the customer sees. Delivery and packaging appear at checkout.

GST (5% on food, paid by Ninjasu under section 9(5) as the e-commerce operator) is added on the bill and rounded to a whole rupee. It passes through and is never Ninjasu revenue. The rate and what it applies to are for the CA to confirm.

Done by the team, outside the code

  • The restaurant agreement and the commission notice period.
  • The rule that the payout is never above the dine-in price.
  • Payouts, by hand, from a settlement export.
  • COD cash: the rider remits it to Ninjasu.

Recorded by the code

  • Per order line: split price and menu price.
  • Per order: payout, commission, rate used.
  • Checkout charges as separate rows.
  • The rate in force at checkout, locked on the order.

New session

Starting the build

  1. Load context

    Run /focus. It reads the tracker, the plan and the reviews. Open schedule-implementation-order.md and pick the first row of the tracker that is not done.

  2. Confirm a clean start

    Backend on main, level with origin, no changes. Branch from origin/main, for example feature/schedule-service-areas. No worktrees.

  3. Work one task at a time

    Brief with /gcp, tests first, then the change. Run hand-run SQL on a scratch Neon branch, never on production. Run the full test suite and eslint, not typecheck alone. Re-check anything Codex reports.

  4. Ship in this order

    Run the additive SQL in production first (the boot guard stops the app if a table is missing), then merge the draft PR (main auto-deploys), then read docker logs ninja --tail 80. A 502 for about 30 seconds is normal. Eat Now must behave exactly as before.

  5. Record progress

    Update the Status column in the tracker table and commit it with the slice. Changes to the plan itself go to a separate session.

  6. Pick the model for the work

    Phase 2b (payment core) and design questions: Opus. Screens in the web, customer and rider apps: Sonnet. Switching models mid-session re-reads the whole context, so start a fresh session per phase.

How each phase reaches production: additive SQL, then merge with the feature off, then verify nothing changed for Eat Now, then enable for the pilot area only. Rollback is switching the area's Schedule flag off; open groups are refunded or finished from ops, and evidence tables are never dropped.
